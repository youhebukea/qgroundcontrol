# LINTOR-GCS（联涛智控版 QGC）修改与编译发布指南

本文档完整记录把 QGroundControl 定制为联涛智控自有产品 **LINTOR-GCS** 所做的全部修改、
编译环境的搭建方式、依赖缓存的复用方案，以及日常编译发布的标准流程。借助本文档可以从
零开始在一台新机器上复现整个编译发布过程。

---

## 1. 修改总览：做了哪些工作

### 1.1 核心机制

采用 QGC 官方的 **custom/ 覆盖目录**机制（见 `docs/en/qgc-dev-guide/custom_build/custom_build.md`）：
源码根目录存在 `custom/` 时，根 `CMakeLists.txt`（第 60-73 行）自动启用定制构建，
在 `project()` 之前加载 `custom/cmake/CustomOverrides.cmake` 覆盖品牌变量，并编译
`custom/src/` 下的品牌插件。**上游源码零改动**（`git status` 中只有 `custom/` 一个
新增目录），因此 `git pull` 升级上游永远不冲突。

### 1.2 三层定制

```text
第 1 层  CMake 变量覆盖   → 应用名/公司名/版权/包名/各平台图标路径
第 2 层  品牌插件         → QML 资源 URL 拦截器 + 官方更新检查断开 + 下载链接替换 + 中文窗口名
第 3 层  资源覆盖         → Logo/帮助页整页替换；窗口图标同路径直接覆盖
```

### 1.3 修改清单（全部位于 custom/ 内）

| 文件 | 作用 |
| --- | --- |
| `cmake/CustomOverrides.cmake` | 品牌变量覆盖（下表），含 5 个平台图标路径覆盖 |
| `src/BrandPlugin.h/.cc` | `QGCCorePlugin` 子类：安装 `QQmlAbstractUrlInterceptor`（`qrc:/x` → `qrc:/Custom/x`）；`stableDownloadLocation()` 指向 `lintor.cn`（同时断开 QGC 官方版本检查）；`QGuiApplication::setApplicationDisplayName("联涛智控地面站")` 设置中文窗口标题 |

## 2. 一次性环境搭建（新机器 / 重装系统后）

| 组件 | 版本 | 用途 | 安装方式 |
| --- | --- | --- | --- |
| VS2022 BuildTools | MSVC 14.44（v17.x） | C++ 编译器 | 安装时勾选"使用 C++ 的桌面开发"工作负载（含 MSVC + Windows SDK） |
| CMake / Ninja | 4.4.3 / 1.12+ | 构建系统 | `pip install cmake ninja` |
| Qt | 6.11.1 msvc2022_64 | 应用框架 | 见下方 aqt 命令 |
| NSIS | 3.x | 安装包生成 | 官网下载或 `winget install NSIS.NSIS`（装到 `C:\Program Files (x86)\NSIS`） |
| Pillow | 12.x | 素材再生成 | `pip install pillow`（仅改 Logo 时需要） |

Qt 安装（模块清单必须齐全，来自 `.github/build-config.json`）：

```bash
python -m pip install aqtinstall
python -m aqt install-qt windows desktop 6.11.1 win64_msvc2022_64 -O D:/qgc/Qt ^
  -m qtgraphs qtlocation qtpositioning qtspeech qtmultimedia qtserialport ^
     qtimageformats qtshadertools qtconnectivity qtquick3d qtsensors qtscxml ^
     qtwebsockets qthttpserver
```

装完后 Qt 位于 `D:\qgc\Qt\6.11.1\msvc2022_64`。

**机器级环境脚本** `C:\Users\tian_\qgc_build_env.bat`（手动执行单条 cmake 命令时先调它）：
设置 `vcvars64`（MSVC 环境）、`QT_ROOT_DIR`、`CPM_SOURCE_CACHE`（见第 3 节）、pip 工具与 NSIS 的 PATH。

## 3. 依赖缓存：一次下载，永久复用（本次新增）

### 3.1 原理

QGC 用 CPM（CMake Package Manager）在 configure 阶段自动下载约 22 个第三方库源码
（MAVLink、SDL3、expat、geographiclib、libarchive、libosmium、px4-gpsdrivers、
vulkanheaders、ulog_cpp、zstd 等，合计 **1.3GB**）。

- 不做任何配置时，缓存默认放在**源码树内** `.cache/CPM`（`CMakeLists.txt:147`）——
  删 build 目录不会重新下载，但重新 clone 会丢。
- QGC 支持环境变量 `CPM_SOURCE_CACHE`（`CMakeLists.txt:144`）把缓存指向源码树之外。

### 3.2 本次已完成的迁移

```text
缓存位置：D:\qgc\cpm-cache   （22 个包，1.3GB，已从 .cache/CPM 迁出）
生效方式：qgc_build_env.bat 与 custom\tools\release.bat 均已设置
          CPM_SOURCE_CACHE=D:\qgc\cpm-cache
```

**效果**：重 clone 仓库、删 `build\` 目录、切分支、换到同盘符新目录——只要
`D:\qgc\cpm-cache` 还在，configure 全部依赖**零下载**直接复用。

### 3.3 什么时候才会重新下载

| 场景 | 是否下载 |
| --- | --- |
| 日常增量/全量编译、打包 | ❌ 不下载 |
| 删除 `build\` 后重新 configure | ❌ 不下载（源码缓存还在） |
| 上游升级了某依赖的版本号（CPM tag 变化） | ⚠️ 仅增量下载该包（几十 MB） |
| `D:\qgc\cpm-cache` 被删除 | ✅ 全量重新下载 1.3GB |

### 3.4 离线/换机部署

把以下两个目录整体拷贝到新机器同路径（或改脚本中路径），即可**完全离线**完成编译：

```text
D:\qgc\cpm-cache          ← CPM 依赖源码缓存（1.3GB）
D:\qgc\Qt\6.11.1          ← Qt SDK（约 3GB）
```

其余（MSVC、NSIS、pip 包）都是一次性的标准安装，无法简单拷贝，需按第 2 节安装。

## 4. 快速编译发布流程（日常用这个）

### 4.1 一条命令

```bat
D:\qgc\qgroundcontrol\custom\tools\release.bat
```

脚本自动完成：MSVC 环境 → configure（显式传入 CPM 缓存路径）→ 编译 → NSIS 打包，
并打印产物路径。首次在新 build 目录约 40-60 分钟，之后增量通常 **3-10 分钟**。

| 参数 | 用途 | 耗时预期 |
| --- | --- | --- |
| `release.bat` | 日常增量发布 | 3-10 分钟 |
| `release.bat clean` | 清空 build 后全量重编（改了 CMake/切换大版本/排查疑难时） | 40-60 分钟 |

> 编译并行度由脚本内 `BUILD_JOBS=6` 控制（默认按 16GB 内存设定）。依赖缓存路径由脚本内
> `CPM_SOURCE_CACHE` 指定并显式传给 configure——不依赖系统环境变量，复制到任何机器改
> 这一个文件即可。脚本内文字保持英文是为规避 cmd 对 UTF-8 中文批处理的解析问题（见 FAQ）。

### 4.2 产物与验证

```text
build\Windows\LINTOR-GCS-installer-AMD64.exe          ← 发布件（92MB，发给用户的唯一文件）
build\Windows\LINTOR-GCS-installer-AMD64.exe.sha256   ← 校验文件
build\Windows\Release\LINTOR-GCS.exe                  ← 裸主程序（50MB，勿单独分发，缺 Qt DLL）
```

发布前检查单：

```powershell
# 1. 校验和
Get-FileHash build\Windows\LINTOR-GCS-installer-AMD64.exe -Algorithm SHA256   # 对比 .sha256 文件
# 2. 品牌元数据
(Get-Item build\Windows\LINTOR-GCS-installer-AMD64.exe).VersionInfo | fl ProductName, CompanyName
# 3. 冒烟（解压目录中的部署版可直接运行）
build\Windows\_CPack_Packages\Windows-AMD64\NSIS\LINTOR-GCS-installer-AMD64\Runtime\bin\LINTOR-GCS.exe
```

### 4.3 手动三步版（想理解/控制每一步时）

```bat
call C:\Users\tian_\qgc_build_env.bat

:: ① 配置（首次约 7 分钟；-D 参数与 release.bat 保持一致）
cmake --preset Windows -DCPM_SOURCE_CACHE=D:\qgc\cpm-cache -DQGC_STABLE_BUILD=ON ^
      -DQGC_ENABLE_GST_VIDEOSTREAMING=OFF -DQGC_BUILD_TESTING=OFF -DQGC_ENABLE_WERROR=OFF

:: ② 编译
cmake --build build\Windows

:: ③ 打包（内部 = cpack -G NSIS -C Release，会先跑 windeployqt 部署 Qt）
cmake --build build\Windows --target qgc-package
```

**为什么打包用 `--target qgc-package` 而不是直接敲 cpack**：该目标封装了正确的
工作目录与配置文件（build\Windows\CPackConfig.cmake）。直接在错误目录跑
`cpack` 会报 `CPack project name not specified`——这是本次实际踩过的坑。

## 5. 完整流程详解

```text
① configure（cmake --preset Windows）
   ├─ 检查编译器/Qt 工具链（qt.toolchain.cmake，由 QT_ROOT_DIR 定位）
   ├─ 检测 custom/ 目录 → QGC_CUSTOM_BUILD=ON → 加载品牌覆盖 → 检测品牌插件
   ├─ 生成 build/Windows/qgc_version.h（版本号由 git describe 从 tag 提取）
   ├─ CPM 从 D:\qgc\cpm-cache 取 22 个依赖源码（命中缓存=零下载）
   └─ 输出确认点：
        "QGC: Custom build directory detected: custom"
        "QGC: Adding Brand (custom overlay) plugin"
        "Windows Platform: Icon: .../custom/res/icons/lintor.ico"

② build（ninja 并行编译）
   └─ 产物 build/Windows/Release/LINTOR-GCS.exe（含品牌资源，exe 属性为公司信息）

③ qgc-package
   ├─ 执行 install 规则 + windeployqt 部署 Qt DLL/QML 模块/插件（80+ DLL）
   ├─ ValidatePackageVersion 校验版本号
   └─ makensis 生成 LINTOR-GCS-installer-AMD64.exe + .sha256
```

## 6. 版本发布规范

1. **版本号**：来自 git tag，无需改代码。发布前打 tag：
   `git tag v1.0.0 && git push origin v1.0.0` → 安装包与"关于"显示 1.0.0
   （不打 tag 时显示 5.0.3 等上游版本或 v0.0.0 占位）。
2. `QGC_STABLE_BUILD=ON` 已固化在 release.bat 中：应用名不带 " Daily" 后缀，
   产品设置空间干净。
3. 标准发布动作：打 tag → `release.bat clean` → 检查单（4.2 节）→ 分发 exe + sha256。

## 8. FAQ（含本次实际踩过的坑）

**Q：编译报 `setApplicationDisplayName 不是 QCoreApplication 的成员`**
A：该 API 属于 `QGuiApplication`。已在 BrandPlugin.cc 修正（include `<QtGui/QGuiApplication>`）。

**Q：cpack 报 `CPack project name not specified`**
A：两种触发方式——① 在源码根目录而不是 build\Windows 里运行了 cpack；② CMake 4.x 生成的
CPackConfig.cmake 缺 `CPACK_PROJECT_NAME`。解决办法就是统一用
`cmake --build build\Windows --target qgc-package`（release.bat 已如此）。

**Q：窗口标题出现 " Daily" 后缀**
A：`QGC_STABLE_BUILD` 未开。release.bat 已带 `-DQGC_STABLE_BUILD=ON`。

**Q：configure 阶段大量 Downloading...**
A：CPM 缓存未生效。确认环境变量 `CPM_SOURCE_CACHE=D:\qgc\cpm-cache` 存在且目录内有 22 个包
（release.bat 是显式传 `-DCPM_SOURCE_CACHE` 的，不依赖环境变量）。

**Q：切换 CPM 缓存路径后第一次编译特别慢**
A：正常且只发生一次——`_deps` 构建目录记录的是旧缓存源码路径，切换后依赖需要重新构建一次
（源码从新缓存复用，无网络下载），之后恢复增量速度。

**Q：想出 ARM64 原生包**
A：`python -m aqt install-qt windows desktop 6.11.1 win64_msvc2022_arm64 -O D:/qgc/Qt`，
再设 `QT_ROOT_DIR=...msvc2022_arm64`、`QT_HOST_PATH=...msvc2022_64`，用 `Windows-arm64`
预设，产物为 `LINTOR-GCS-installer-ARM64.exe`。32 位 x86 无法支持（Qt 6.11 无 32 位包）。

**Q：编译中途报 `C3859 未能创建 PCH 的虚拟内存` / `C1076 编译器限制: 达到内部堆限制`**
A：并行度过高导致内存耗尽（每个 cl.exe 加载 PCH 约占 1.5-2GB）。release.bat 已内置
`BUILD_JOBS=6`（按 16GB 内存机器设定）；内存更大的机器可在脚本顶部调大，内存 8GB 的机器
建议再降到 3-4。另外编译前先关闭正在运行的 LINTOR-GCS.exe（会占内存）。

**Q：release.bat 报一堆乱码"不是内部或外部命令"**
A：bat 文件必须保持**纯 ASCII**（cmd 按 GBK 解析批处理，UTF-8 中文注释会导致行解析错乱）。
所以脚本内说明文字都是英文，中文说明一律写在本指南中。

**Q：MSVC 增量编译偶发 .obj 文件被占用**
A：关闭正在运行的 LINTOR-GCS.exe / 安装程序预览后再编。
